# 飞书端优化工程方案 v2（单聊通知矩阵版）

> v2 变更（2026-09-09 用户指示）：**不建群聊**。机器人单聊窗口 = 每个用户的通知入口；
> 通知范围扩展到**社区互动**（回复/发帖动态）；机器人窗口提供**常驻入口打开网站（默认社区页）**；
> 手机端浏览布局视网页实际兼容情况后续调整。
> 其余继承 v1：主攻通知触达升级；公网可达性不确定 → 纯出站零回调设计；自建应用凭证已在用。

## 一、总体形态

```
飞书机器人（自建应用，已在用）
 ├─ 单聊窗口 = 个人通知中心（全部卡片触达这里）
 │    · 报名确认 / 审核结果 / 活动开始提醒 / 预约确认（既有+新增）
 │    · 社区动态：我的帖子被回复、我的评论被回复（新增）
 │    · 新报名待审（仅管理员收）
 └─ 机器人自定义菜单（常驻入口）→ 打开网站，默认社区页
```

## 二、批次划分

### 批次 A · 报名链路卡片（2026-09-09 实施后更新）

| 项 | 内容 | 状态 |
|---|---|---|
| A1 | 报名者收「报名成功」确认卡片 | **已存在**（notifyAct：站内通知+飞书卡片一体，预约同款） |
| A2 | 审核结果卡片（通过/驳回 + 原因） | **数据前提缺失，并入数据调整批**——见下「数据前提缺口」 |
| A3 | 管理员收「新报名」卡片（报名人/部门/联系方式 + 「去管理端查看」按钮直达 #admin） | **本轮已实现**（activities.js：notifyAdminsOfSignup + adminSignupCard，fire-and-forget） |

**数据前提缺口（A2 与「数据方面的调整」的衔接点）**：
- `registrations` 表（旧报名，有 pending/approved/rejected 审核流）**没有 user_id/open_id 列**——审核结果无法定位到飞书用户，发不了个人卡；
- `works` 表（社区作品，有审核流）同样**没有 user_id**；
- `activity_signups`（新表单报名）有 user_id 但**没有审核状态位**（报名即成功，无审核环节）。

**建议二选一**（属于数据调整批的决策）：
1. 给 `registrations`/`works` 加 `user_id` 列（迁移 SQL + 提交端带上登录身份）→ 老审核流直接可发审核结果卡；
2. 或确认旧 `registrations` 链路废弃，新报名以 `activity_signups` 为唯一入口并给它加 `status` 审核位 → 审核结果通知走新表（推荐，表更干净）。

### 跳转地址策略（回答「地址固定吗，能否写两种」）

**结论：飞书侧只能配一个固定地址，写不了两种。** 机器人自定义菜单是一个固定 URL；卡片按钮也是单值（SITE_INTRANET_URL 环境变量）。应对策略分两段：

- **现在（本地测试期）**：先**不配** SITE_INTRANET_URL、不配菜单——卡片会自动省略按钮（代码已支持），通知正文完整送达，零影响；等地址方案定了再配，属纯配置动作。
- **中期（固定地址）**：给站点挂一条 Cloudflare 隧道（与 feishu-mcp 同款方式），得到形如 `https://site.xxx.asia` 的固定公网 HTTPS 域名——热点/网络随便切地址不变；顺带满足将来卡片回调（直审）的公网前提。内网 IP 方案（主机名或固定 IP）不推荐：热点切换就失效。

配置时机：卡片按钮 = 改环境变量重启即生效；机器人菜单 = 开放平台配一次发布即生效（两者可不同时配）。

### 批次 B · 社区动态通知（新增需求）

| 项 | 收卡人 | 触发点 |
|---|---|---|
| B1 我的帖子被评论 | 帖子作者 | 社区评论创建接口 |
| B2 我的评论被回复 | 被回复的评论者 | 楼中楼/回复接口（视表结构定） |
| B3 新帖通知管理员（可选，默认关） | admins | 社区发帖接口 |

- 需先读 community.js / work-comments.js 路由与表结构后细化字段映射；
- 卡片形态：「你的帖子收到新评论」+ 评论摘要 + 「去查看」按钮（#community）。

### 批次 C · 机器人窗口常驻入口（开放平台配置，非代码）

飞书自建应用支持「机器人自定义菜单」：配置后每个用户在机器人单聊窗口常驻一个入口按钮，点击在飞书内直接打开网页。配置步骤（朱曦策在开放平台操作，约 2 分钟）：
1. 开放平台 → 企业自建应用（丽珠 AI 社区用的那个）→ 应用功能 → 机器人；
2. 底部「自定义菜单」→ 添加菜单：名称「进入社区」，类型「跳转到网页」；
3. 网页地址填站点社区页（例：`http://<内网IP>:8787/#community`，即同事浏览器能打开的那个地址）；
4. 保存并发布（菜单变更需发布版本生效）。

发布后：用户把机器人会话置顶即可获得常驻入口——点开就是社区页。

### 批次 D · 移动端浏览布局（视兼容情况后续）

- 飞书手机端 webview 打开网站后，逐页检查布局（首查：社区页、活动列表、报名表单——这三个是移动高频页）；
- 问题典型为：横版导航、表格溢出、弹窗宽度；按页逐个适配（媒体查询 + 移动导航抽屉）；
- 触发条件：批次 C 上线后实际用手机访问过一轮再定改哪些，避免盲改。

### 后续可选（公网确定后再启动）

- 卡片上直接「通过/驳回」审核（需卡片 action 回调 + 公网 HTTPS 地址）；
- 真·飞书日历日程（替代 .ics 下载）。

## 四、验收标准

1. 批次 A：报名→报名者确认卡 + 管理员待审卡；审核→结果卡（通过/驳回两态文案区分）；各发一条真卡片验收；
2. 批次 B：他人评论我的帖子 → 我收卡；自评不通知；卡片含评论摘要与「去查看」；
3. 回退链：凭证失效时站内通知仍达、接口不受影响；通知发送全部异步；
4. 防重发：同一 signup 幂等一次；重复审核只推一次结果；
5. 批次 C：配置发布后，机器人窗口出现「进入社区」入口，点击直达社区页。
