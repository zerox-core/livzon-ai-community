## 二、P0 前置 Bug 修复

### P0-1 报名表原始字段名暴露（field_a / field_b / field_c）— 双端修复

- **管理端拦截**：`afCollect` 保存表单时，自定义字段 label 为空**直接阻断保存**（错误提示「自定义字段必须填写标签」），不再静默以 key 兜底——杜绝新脏数据。
- **用户侧兜底**：渲染层新增 `sigSafeLabel(f, fi)`——label 为空、或 label 与 key 相同且形如 `field_\w+` / `f_xxx` 时，展示「补充信息 N」，旧脏数据不再裸露 key。
- **存量数据**：不自动猜标签（计划约定），只报清单。检查 SQL 见附录 A，由管理员照单补录中文标签。

### P0-2 部门自动读取为空 — 登录解析 + 存量懒回写

- `server/lark-client.js` 新增 `getDepartmentName(deptId)`：复用 tenant_access_token 调 `GET /open-apis/contact/v3/departments/:id`，实例级 Map 缓存，任何失败返回空串**不阻断登录**。
- `server/routes/auth.js` upsertUser：登录时将 `department_ids[0]` 解析为部门名后写入 `users.department`（解析失败保留原值）。
- `server/routes/my.js` /profile：读到的 department 若不含中文（形如纯 ID），现场调 LarkClient 解析并 **UPDATE 回写**——存量用户无需脚本，首次访问个人中心即自动治愈；此后 `userSnapshot`（报名落库的 dept）一并正确。
- 报名表部门字段旁加说明：「取自飞书组织架构；如显示为编号，稍后刷新会自动更新为部门名」。

### P0-3 页面卡顿（录屏两次冻结）

- **代码侧已做**：报名页加载加**骨架屏**（四节占位 + shimmer 动画，`prefers-reduced-motion` 自动停用）——消除「4 个接口未返回时页面看似卡死」这一最大嫌疑项。
- **待运行时取证（Codex 侧）**：Chrome Performance 面板录「进报名页 → 填表 → 上传」路径，定位 canvas 动画 / innerHTML 拼接的长任务；服务端对照 server.log 对应时间片。若仍有长任务，修复方向为卡顿区块分帧（requestIdleCallback）。

### P0-4 活动记录凌晨时间 — 确认为前端格式化 Bug，已修复

- **取证结论**：服务端存 UTC ISO 串，前端 3 处格式化函数直接按 UTC 字面截断输出（未转本地时区）——凌晨时间 = UTC+8 时差，**确认为 bug**。
- **修复**：3 处 fmt 统一改为 `new Date(s)` 本地时间渲染（getFullYear/getMonth/getDate/getHours/getMinutes + 补零），isNaN 兜底原样截断展示。

## 三、P1 报名表改造

### P1-1 布局重做（四节分组）

报名表由单列平铺重构为编号分节卡片：

1. **① 基本信息**：姓名 / 部门只读预填，节头说明「自动读取，无需填写」；
2. **② 联系方式**：绑定邮箱脱敏只读展示（如 `te***@example.com`，节头注明「报名凭证发送至此」）+ 备用联系方式输入（选填，placeholder「手机 / 邮箱」）；
3. **③ 作品文件**（needUpload 时）：双模式切换（见 P2）；
4. **④ 补充信息**：组队情况 + 活动自定义字段，每字段带 hint。

配套 CSS（`sig-sec` 分节卡、`sig-loading` 骨架、`sig-mode` 模式切换钮、`sig-assets` 资产列表、`sig-draft-bar` 恢复条）全部内联注入 app.js，未新增样式文件。

### P1-2 字段规则

- 姓名：只读预填（沿用）；
- 部门：P0-2 数据修复后只读预填；
- 备用联系方式 + 绑定邮箱脱敏展示——**待确认① 按默认方案执行**：users 表无 mobile 字段，首版展示绑定邮箱脱敏，后续可接飞书 users.info mobile。

### P1-3 自动草稿（localStorage）

- key：`signup_draft:{activityId}:{userId}`（登录态 userId 隔离，两活动互不干扰）；
- 保存：input 事件 **600ms debounce**，捕获 contact / team / 全部自定义字段；
- 恢复：进入报名页检测草稿 → 顶部恢复条「⏳ 检测到未提交的草稿（时间）」+「清空」按钮；radio / checkbox / 文本框按字段逐项恢复，不整体覆盖；
- 清除：提交成功自动删除；用户点「清空」立即删除；文件不入草稿（只记已选资产引用）。
- 冒烟实测：保存 → 刷新 → 恢复（含自定义字段）→ 清空，全链路通过。

## 四、P2 上传链路分流

### P2-1 已有资源直接选用（核心价值点）

- 报名表「作品文件」区双模式：**⬆ 上传新文件**（默认）/ **▣ 从我的作品选择**；
- 「从我的作品选择」：拉取 `/api/assets?mine=1&limit=100`，单选列表展示名称 / 大小 / kind，带「报名作品」来源标签（见 P2-3）；无资产时展示引导入口（P3 跳转）；
- 提交体升级：`{contact, upload, assetId, response}`——选用资产时 `upload` 传 null、`assetId` 传所选资产 id；
- **服务端 `POST /:id/signup` 重构**：
  - 收到 assetId → getAsset 校验**归属权**（非本人资产一律 400），upload 快照由服务端从资产记录重建（不信任前端快照）；
  - 直传模式保持 uploadFirst → 现场新传天然登记 assets 进「我的资源」（原链路不动）；
  - `needUpload && !upload.storage_url && !assetId` 时拦截「请上传作品文件，或切换到『从我的作品选择』」；
  - rules 新增 `assetId: {type:'string', max:64}` 校验。

### P2-2 分流引导文案

- 上传区固定说明：「支持 zip / tar.gz / rar 等压缩包、pdf / doc / md 文档、mp4 等视频，单个 ≤50MB」；
- 资产列表为空 / 不会压缩的兜底：常驻入口「去『我的 → 资源』上传 / 登记 →」带参数跳个人中心（P3 闭环）。

### P2-3 来源标签

- 报名场景上传的资产 `source = 'signup:{activityId}'`（新字段，见迁移 014）；日常上传 source 为空——两类不混；
- 个人中心「我的资源」列表：source 以 `signup:` 开头的资产显示「报名作品」徽标。

## 五、P3 + P4

### P3 个人中心聚光灯引导（三件套）

- 入口：报名表跳转 `/#my?guide=upload&back=signup:{activityId}`；
- 落地：自动滚动到「我的资源」区，**聚光灯遮罩**（box-shadow 9999px 挖洞高亮上传面板，pointer-events:none 不阻挡操作）；
- 教程卡：3 步说明「上传压缩包 → 回报名表 → 选用该资源提交」，按钮「知道了」+「返回报名表」；
- 回跳：「返回报名表」解析 back 参数回到 `#signup?activity={activityId}`，报名表重新渲染（新上传资产进入「从我的作品选择」列表）；
- `prefers-reduced-motion` 无过场动画，符合项目规范。

### P4 GitHub 地址识别（程序面板增强）

- **前端**：仓库地址输入框实时识别——输入含 `github.com/` 即展开 gh-box（gitlab 域保持原流程零回归）；面板显示「识别 README → 预览」按钮，预览区展示 README 前 4000 字符；提交时 README 全文（含抓取时间与仓库路径头）自动附加进 agent_report；
- **服务端**：`POST /api/assets/github-readme` 只读代理——正则白名单严格校验 github.com 仓库 URL（支持 /tree/分支 与 #anchor），尝试分支 [显式 → main → master] × [README.md, readme.md]，AbortController **10s 超时**，**200KB 截断**，返回 `{readme, repo, path, fetchedAt}`；
- **待确认③ 按默认方案 A（服务端代理）实现**：若服务器无公网出口，接口将返回错误，前端提示抓取失败、不阻断登记——后续若确认内网不可出网，可降级前端直链方案，接口无需删改。

## 七、数据库迁移（014）

`server/sql/014_signup_asset_source.sql`（幂等，可重跑）：

```sql
ALTER TABLE assets ADD COLUMN IF NOT EXISTS source TEXT NOT NULL DEFAULT '';
ALTER TABLE activity_signups ADD COLUMN IF NOT EXISTS asset_id TEXT REFERENCES assets(id) ON DELETE SET NULL;
```

- `assets.source`：来源标记（空 = 日常上传，`signup:{activityId}` = 报名作品）；
- `activity_signups.asset_id`：选用已有资产时的引用；资产被删除时置空（ON DELETE SET NULL），与报名快照解耦。

**执行（Codex 侧）**：`node server/sql/run_migrate.js`（启动三信号验证前先跑）。

## 附录 A：存量脏字段检查 SQL（P0-1 数据清单）

```sql
-- 列出所有 label 缺失或等于 key 的自定义字段（照单补录中文标签）
SELECT f.activity_id, idx AS field_index, j.key, j.label
FROM activity_signup_forms f,
     jsonb_array_elements(f.profile->'fields') WITH ORDINALITY AS j(elem, idx)
WHERE j.elem->>'label' IS NULL OR j.elem->>'label' = '' OR j.elem->>'label' = j.elem->>'key';
```
